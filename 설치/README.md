# 새 Supabase 프로젝트에 붙일 때 — 빠뜨리면 안 되는 것

넘겨받은 분이 자기 Supabase 로 옮길 때, **이 차례 그대로** 하면 된다.
하나라도 빼면 화면은 뜨는데 무언가가 조용히 안 된다.

## 1. 프로젝트 만들기
- 지역은 **Northeast Asia (Seoul)**
- 만든 뒤 `Project Settings → API Keys` 에서 두 가지를 복사한다
  - **Project URL** (`https://xxxx.supabase.co`)
  - **Publishable key** (`sb_publishable_…`) — 🔴 `Secret key` 는 절대 쓰지 않는다

## 2. 앱에 주소·열쇠 넣기
`js/01a-설정.js` 의 **두 줄만** 갈아끼운다. 다른 파일은 손대지 않는다.

## 3. 표 만들기
`설치/표만들기.sql` 을 SQL Editor 에 붙여 넣고 실행.
→ 끝에 표 10개가 나와야 한다.

## 4. 사진 통 만들기  🔴 이걸 자주 빠뜨린다
`설치/사진통만들기.sql` 을 실행.
→ 안 하면 **메모·체크리스트·영농일지의 사진 올리기가 조용히 실패한다.**
   화면은 멀쩡히 뜨기 때문에 한참 뒤에야 안다. (2026-09-17 실제로 그랬다)

## 5. 이메일 확인 끄기  🔴 이것도 빠뜨리기 쉽다
`Authentication → Sign In / Providers → Email` 에서 **Confirm email 을 끄고 Save.**
→ 안 끄면 가입해도 확인 메일을 기다리느라 아무도 못 들어온다.
   쓰는 사람이 두세 명뿐이라 메일 확인은 짐만 된다.

## 6. 확인
브라우저에서 회원가입 → 로그인 → 아무 화면에서 한 줄 넣어 보고,
**다른 기기에서도 그 줄이 보이는지** 본다. 한 기기만 보고 끝내면 안 된다.

---

## 알아둘 것

- **anon(Publishable) 열쇠는 코드에 박혀 있어도 된다.** 남이 봐도 되는 열쇠다.
  막는 것은 열쇠가 아니라 Supabase 쪽 규칙(RLS)이다 — 로그인 안 하면 표가 통째로 안 열린다.
- 표는 칸이 다섯뿐이다 — `id` · `내용`(jsonb) · `삭제됨` · `수정시각` · `수정자`.
  앱이 서버에 질의하지 않고 전량을 받아 브라우저에서 계산한다. 그래서 칸을 늘릴 일이 없다.
- 지운 자료는 행을 지우지 않고 `삭제됨=true` 로 둔다.
